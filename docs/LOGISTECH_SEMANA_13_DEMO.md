# Guía de demostración de Semana 13

1. Abra PowerShell 7 en la raíz, inicie Docker Desktop y active el motor Linux. Use el archivo local F7 y sus secretos de ensayo. Si trabaja desde otra máquina, copie `deploy/production.env.example` a `.env.f7-candidate`, configure `PUBLIC_DOMAIN=localhost` y genere los archivos TLS y secretos siguiendo la guía. [Preparación de secretos](AWS_F7_GUIA.md)
2. Ejecute `pwsh -NoProfile -File scripts/start_week13.ps1`. Abra `https://localhost:8453` con la CA del ensayo confiada por el navegador. Extraiga la CA con `docker cp logistech-week13-proxy-1:/data/caddy/pki/authorities/local/root.crt root-week13.crt` y mantenga su archivo fuera del repositorio.
3. Genere credenciales con `docker exec logistech-week13-backend-1 python manage.py create_demo --namespace exposicion13 --output /tmp/exposicion13.json`. Consulte el archivo en privado con `docker exec logistech-week13-backend-1 cat /tmp/exposicion13.json`. Si ya existe, use el archivo existente o elija un espacio de nombres nuevo. Nunca muestre el archivo al proyectar.
4. Entre en `/login` con la cuenta `root` para ver empresas y usuarios. Entre como `admin` para crear, editar, buscar y borrar una categoría sin referencias. Muestre que el operador no puede administrar usuarios y que la cuenta pendiente no tiene empresa asignada. En cajas, registre una, abra el detalle y consulte el QR, la recepción y el historial.
5. Muestre la captura real de página 2 en `docs/evidencias/semana13/e2e-pagination.png` o repita `pagination.spec.js` usando un archivo local de credenciales de ensayo, `PW_BASE_URL=https://localhost:8453` y `PW_REHEARSAL_TLS=true`. La prueba crea 26 categorías ficticias y elimina las propias al terminar. Al aplicar un filtro nuevo, la vista vuelve a la página 1.
6. Consulte PostgreSQL con `docker exec logistech-week13-db-1 psql -U logistech_owner -d logistech -c "SELECT count(*) FROM boxes_box"`. Muestre el esquema editable `docs/MODELO_DATOS.mmd`.
7. Ejecute `pwsh -NoProfile -File scripts/run_week13_load.ps1 -Scenario get -Iterations 100`. El runner prepara un proyecto y volumen independientes, usa HTTPS y conserva el volumen después de detener el proyecto. Para alta pública use `-Scenario register -Iterations 2`. Abra `docs/evidencias/semana13/k6.html` para comparar los ensayos guardados.
8. Ejecute `py scripts/verify_week13_recovery.py` fuera de otras escrituras del ensayo. Muestre el checksum, la restauración comparada, el rechazo de una base que ya existe y la persistencia tras el reinicio.
9. Sin sesión, abra una ruta de la aplicación y observe la redirección. Consulte una ruta inexistente para mostrar 404. Use los resultados E2E para demostrar la renovación tras expirar el acceso.
10. Cuando exista un despliegue autorizado, valide la URL pública con HTTPS, consulte `/api/v1/health/` y compare el SHA e identificadores de imagen con el manifiesto auditado. [Guía de operación y rollback](AWS_F7_GUIA.md)
